02 Overview

Small by construction.

L2 is a compact Linux distribution assembled around a single supervisor and a static userspace. It boots from read-only media, pivots into a 107 KB initramfs, and keeps in memory only what the running system needs.

One supervisor

rcl2 runs as PID 1 and stays resident. There is no service manager layered above it and no second init to replace it.

Static by default

The shell, utilities, package manager and system tooling are static musl binaries. gcompat covers prebuilt glibc programs.

Measured, not assumed

Every figure on this page comes from the project's measured specification, collected on QEMU TCG with standard virtual hardware.

04 Architecture

One binary, two cores.

rcl2 is the init. It starts userspace as PID 1, supervises it, and remains the only resident process of its kind.

C core

Raw syscalls through syscall(2): fork and exec, wait and reap, signals, mounts, console and reboot(2). No libc is linked.

Rust core

A #![no_std] core with no external crates. It parses /etc/rcl2.conf, the kernel command line and /proc/self/statm.

Shared ABI

A pinned #[repr(C)] contract between both cores. Layout assertions are compiled into C and Rust and checked from both sides.

Drop-in init

Replaces the original script/init/init.c with the same mounts, console wording and L2# prompt. l2.rescue=1 opens a rescue shell.

The build path is deliberately non-GNU: clang, rustc, ld.lld and LLVM binutils.

06 Getting started

Boot it in a VM.

Run the launcher from the repository root. QEMU is the supported path; the BIOS profile needs 32 MiB and the UEFI profile 128 MiB.

07 FAQ

Questions

Does L2 run on real hardware?

L2 is designed for x86_64 PCs. The live image supports BIOS and UEFI boot and includes an installer for local disks. Hardware compatibility has not yet been tested; boot and installation results so far come from QEMU.

Why is there no glibc?

Native tooling is static musl. glibc-linked x86_64 binaries run through gcompat 1.1.0 with the musl loader; pthread, math and getpwuid usage are verified.

How are packages built and installed?

l2pm consumes .l2pm recipes and produces .l2p archives, which are newc-cpio images compressed with gzip. It can pack, add, list and remove packages.

How much memory should I allocate?

16 MiB is enough to boot and leaves under 1 MiB for applications. The recommended launcher allocations are 32 MiB for BIOS and 128 MiB for UEFI.

What happens if the system breaks?

Set l2.rescue=1 for a rescue shell. Offline and recovery boot paths are part of the verified checks.
